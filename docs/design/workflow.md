# AIと進めるリデザイン手順

## 進め方

1. 現状のホーム・ブログ一覧・長文記事をデスクトップとモバイルで撮影する。読者、目的、実際のコンテンツを確認。
2. 参考を12件ほど集め、取り入れたい点を一文ずつ残す。3方向に整理する。
3. 同じ実データ・同じページで、構造から異なる3案を作る。画像案は方向選びに使い、動作する証拠とはしない。
4. 「本人らしさ、読みやすさ、目的への到達、モバイル、実装負荷」を各5点で比較。点数には理由を添え、ユーザーが選ぶ。
5. 選択案の色、文字、余白、幅、境界、リンク、フォーカス、動きをデザイントークンにする。DESIGN.mdなどに理由も残す。
6. ホームと代表記事をAstroで実装。microCMSの内容とルートを維持し、架空の実績を追加しない。
7. ブラウザーで撮影・比較し、崩れと使いにくさを直す。型チェック・ビルド・必要な性能測定を実施。
8. 今回の変更だけをコミットし、mainへpush。既存の無関係な未コミット変更を保護する。

## 探索用プロンプト

```text
このrepoの個人サイトのリデザイン方向を3案比較したい。
対象: wato787のプロフィールと技術ブログ。
仮の読者: 技術者仲間。目的: 何をする人か理解し、興味のある記事を読む。
既存のAstro + TypeScript + microCMSを維持する。
参照: docs/design/research.md。既存の文章と写真を確認して使う。

Aは編集・アーカイブ、Bは制作過程の作業机、Cは道具としてのサイト。
同じ文章で比較し、色だけでなく情報構造・文字・写真の使い方を変える。
各案について、第一印象、情報の順序、文字、配色、モバイル、
固有性、実装負荷を説明し、ホームと記事画面の視覚案を示す。
まだ採用を決めず、本番実装に進まない。
公開できる実績が不明なら捏造せず、今ある記事とプロフィールで成立させる。
```

## 参考の渡し方

```text
参考URLとスクリーンショットを添付する。
参照A: 見出しと本文の対比だけ取り入れたい。
参照B: モバイルの記事一覧の密度を参考にしたい。
参照C: 写真の切り抜き方と余白を参考にしたい。
ロゴ・文章・写真をそのまま流用せず、本人の素材で再構成してほしい。
```

## 選択後の実装用プロンプト

```text
選択した案をAstroに実装する。
最初に色・文字・余白・幅・境界・フォーカスのトークンを定義。
静的部分はAstro/CSSを基本に、対話が必要な箇所だけJSを使う。
ホーム、ブログ一覧、記事詳細に同じ規則を適用。
長い日本語タイトル、コード、画像なし、記事0件でも成立させる。
360/390/768/1440px、キーボード、200%拡大、reduced motionで確認。
生成したコードだけで完了せず、表示を撮影して選択案と比較する。
結果は変更点・確認結果・未完了事項を短く報告する。
```

## レビューの記録形式

| 画面・幅 | 観察した問題 | 読者への影響 | 修正 | 再確認 |
| --- | --- | --- | --- | --- |
| 記事 / 390px | 例: コードが画面全体を押し広げる | 本文が読みづらい | コード領域内の横スクロール | 撮影して確認 |

「おしゃれになった」だけでなく、画面上の具体的な改善で評価する。
